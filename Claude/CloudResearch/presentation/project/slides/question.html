01 · Problem and research questions

Clouds hide what our change detector must see

The system. A vision foundation model finds where two images differ, an agent describes the change, and code checks every fact. For now, flood analysis: each road's features go into our model, which predicts flooded or not.

One difficulty · clouds in EO imagery

“Clouds can hide target areas in images taken after disasters. This can lead to labels being inaccurate compared to ground truth due to obscured parts of the imagery. How should we detect clouds in this imagery, handle them, and report them? The goal is results, such as maps of flooded roads, that people can trust.”

Expected contribution: a tested rule for what a change map may say under cloud, a measured label gap, and a test of whether a second date can correct thin cloud.

Working rules. Change is anything that differs between dates, except lighting. Cloud in either image is seen through in preprocessing, so the detector never reads cloud as change.

The system finds where two images differ, describes what the change looks like, and checks the facts in code. Change means anything on the ground, not lighting. Cloud breaks this: it hides the ground, and the human labels are shaped by the same cloud. So we ask what a map can reliably report under cloud, and whether seeing through cloud with the other date finds change as well as clear sky.
